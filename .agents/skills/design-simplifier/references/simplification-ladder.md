# Simplification ladder

Apply these transformations in order before proposing a new surface or control. Stop as soon as the user job is served with materially less cognitive load.

1. **Remove** — delete a step, field, setting, concept, or feature that does not change the outcome.
2. **Combine** — consolidate things that serve the same user job or create competing sources of truth.
3. **Default** — make the normal safe decision for the user; keep an escape hatch when the decision is meaningful.
4. **Infer** — derive an answer from scope, context, history, or existing data instead of asking again.
5. **Hide** — progressively disclose advanced options when they become relevant.
6. **Reframe** — rename or reorganize around the user’s language and intention rather than implementation structure.
7. **Inline** — place action, help, result, or recovery where the user already is.
8. **Mode** — represent related capabilities as modes or states of one tool when the mental model is shared.
9. **Automate** — perform an obvious intermediate step while preserving visibility, control, and truthful status.
10. **Add** — introduce a new surface only when the earlier transformations cannot solve the actual problem.

For each candidate, answer:

- What user decision or effort disappears?
- Which concept or source of truth disappears?
- What is the safe default and how can the user override it?
- What becomes less visible or flexible?
- Does the change preserve scope, authority, privacy, and verified reality?

Warning signs that a rung is being skipped:

- a new navigation item is proposed before testing whether an existing destination can host the job;
- a setting is added to compensate for unclear defaults or terminology;
- a modal is added where inline context or undo would suffice;
- separate workflows are created for a capability that differs only by mode;
- automation hides an important decision, status, or failure;
- a visual redesign is proposed without a journey-level friction claim.
