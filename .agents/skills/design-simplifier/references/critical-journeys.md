# Critical journey map

This is a map of what people are trying to accomplish in OpenPresence. It is intentionally different from [`verify-app`’s feature map](../../verify-app/references/features/README.md), which records routes, selectors, commands, and proof requirements.

Update this map when a user job or cross-surface boundary changes. Keep executable selectors and runtime proof in `verify-app`.

## Create a trustworthy workspace

**Job:** Create an Agent and first Presence, understand who is active, and return later without losing identity or scope.

**Journey:** Onboarding → workspace → Agent/Presence switchers → reload or route change.

**Design questions:** Is the hierarchy legible? Does switching Presence leave the Agent’s mind intact? Is the first useful action obvious?

## Shape the Agent’s judgment

**Job:** Ask the Agent something, teach a durable preference, or understand what it believes without learning infrastructure.

**Journey:** Chat/Teach or Rehearsal → response/receipt → proposal or rehearsal feedback → inspect durable state when appropriate.

**Design questions:** Are conversation, teaching, memory, Taste, and proposals distinct but understandable? Is the user told what changed, what is pending, and what did not change?

## Decide what matters now

**Job:** See meaningful social attention, understand the Agent’s decision, and act only when operator judgment is needed.

**Journey:** Activity → event/decision context → Review or relevant recovery → return to Activity.

**Design questions:** Is the next action obvious? Are observation, decision, execution, delivery, and verified outcome distinct? Does Review avoid becoming a second dashboard?

## Give the Agent responsibility

**Job:** Define an outcome and timing, then understand whether responsibility is due, working, blocked, failed, or completed.

**Journey:** Schedule → Assignment details → Agent consideration/execution → truthful status/outcome.

**Design questions:** Does the operator specify the outcome rather than micromanage method? Is “scheduled” clearly different from “published” or “completed”?

## Rehearse safely

**Job:** Test how an Agent might respond in a realistic social situation without affecting the live world or silently changing identity.

**Journey:** Playground/Rehearsal → simulated event → cognition/intent/execution trace → feedback or reset.

**Design questions:** Is Sandbox isolation unmistakable? Can the user understand the decision without being coached toward an expected answer? Are rehearsal findings separate from durable identity and live outcomes?

## Give a Presence a place to exist

**Job:** Configure where an Agent exists, how it appears there, what it may do, and how the connection is performing.

**Journey:** Channels/Presence settings → connection and identity configuration → persistence → Activity or live surface.

**Design questions:** Are intention and scope visible before Bridge/API details? Do Review, Custom, and connection states reveal real behavior rather than merely changing labels?

## Notice people and relationships

**Job:** Direct attention toward relevant sources, recognize people, and maintain useful relationship context without confusing search with contact.

**Journey:** Watching → observed content/person context → People → relationship facts and open loops.

**Design questions:** Is attention distinct from authority? Is a search lead clearly different from an observation, person, or relationship?

## Learn and grow without becoming a dashboard operator

**Job:** Understand what is resonating, what the Agent is learning, and where to improve qualified audience growth.

**Journey:** Growth/Analytics/Usage/Feed or contextual evidence → interpretation → next social decision.

**Design questions:** Do metrics inform judgment rather than replace it? Are incomplete measurements and scope boundaries honest? Does the surface help the Agent become someone people want to hear from?
