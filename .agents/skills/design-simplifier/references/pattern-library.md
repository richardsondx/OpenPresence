# Pattern library

Organize precedents by the interaction problem they solve, not by company or brand. These are reusable hypotheses, not mandates. When using one, record the source, context fit, adaptation, and what should not be copied.

## First useful value

- Start with a focused task and a good default.
- Explain the next step in the empty state.
- Defer account-wide configuration until it becomes necessary.

## Advanced configuration

- Keep the common path compact.
- Reveal advanced controls contextually or behind an explicit “more” affordance.
- Preserve the current summary so users can understand what the advanced choice changed.

## Shared capability with different intent

- Use one surface with clear modes or states when the underlying job and context are shared.
- Keep the mode visible and preserve work while switching.
- Split destinations only when permissions, scope, lifecycle, or mental model genuinely differ.

## Operator review and recovery

- Make “what needs my judgment” a focused queue.
- Put approve, edit, reject, retry, cancel, or recover beside the relevant item.
- Explain why action is needed and what state follows; do not imply delivery before verified outcome.

## Destructive or uncertain actions

- Prefer preview, undo, draft, reversible state, and clear consequences.
- Use confirmation when the action is genuinely destructive or difficult to reverse, not for every ordinary action.

## Empty, partial, and error states

- Say what is absent or unavailable in human language.
- Give one useful next action or a truthful reason to wait.
- Preserve partial truth; do not fill missing data with fabricated health, activity, or success.

## Scope and identity

- Show the active Agent and Presence near actions that can affect identity, memory, privacy, or authority.
- Use a searchable Agent switcher for many Agents and a compact Presence picker for filtering.
- Keep implementation detail one level away unless it is necessary for the user’s decision.
